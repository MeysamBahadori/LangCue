# LangCue — لنگ‌کیو

**[English README / راهنمای انگلیسی](README.md)**

LangCue یک ابزار سبک برای ویندوز است که **زبان فعال صفحه‌کلید را نزدیک نشانگر تایپ** نمایش می‌دهد. به این ترتیب قبل از تایپ متوجه می‌شوید چه زبانی فعال است. این برنامه متن تایپ‌شده را نمی‌خواند، ذخیره نمی‌کند و ارسال نمی‌کند.

**نسخه:** `0.2.0-preview.1` — پیش‌انتشار آزمایشی؛ هنوز نسخه ۱ نیست.

## ویژگی‌ها

- **چندزبانه:** تمام زبان‌های ورودی قابل‌شناسایی ویندوز با کد زبان نمایش داده می‌شوند؛ مانند EN، DE، FR، AR، HE، UR، RU، ZH، JA و KO. برای فارسی همچنان **فا** نمایش داده می‌شود. زبان‌های سفارشی ناشناخته با شناسه ویندوز مشخص می‌شوند.
- **تشخیص RTL/LTR:** در حالت جلو/عقب Caret، جهت زبان از اطلاعات ویندوز گرفته می‌شود؛ تنها محدود به فارسی نیست و برای عربی، عبری، اردو و زبان‌های راست‌به‌چپ دیگر هم استفاده می‌شود.
- **موقعیت قابل‌تنظیم:** بالا (پیش‌فرض)، جلو، عقب یا پایین نشانگر تایپ با فاصله ۰ تا ۸۰ پیکسل.
- **نمایش زیباتر:** گوشه‌های نرم و ضدپله‌ای همراه با پس‌زمینه نیمه‌شفاف؛ میزان شفافیت پس‌زمینه از ۴۰ تا ۱۰۰ درصد قابل تنظیم است (پیش‌فرض ۷۸ درصد). نوشته روی آیکون کاملاً واضح می‌ماند.
- **پشتیبانی گسترده‌تر از برنامه‌ها:** یافتن Caret از طریق Win32، ‏MSAA و UI Automation؛ در بسیاری از فیلدهای مرورگرهای Chromium و بعضی ابزارهای Electron.
- **منوها و Dropdownها:** تلاش برای نمایش بالاتر از منوهای عادی ویندوز، بدون گرفتن فوکوس تایپ.
- **آیکون اختصاصی** برای برنامه و System Tray، تنظیمات و خروج از طریق Tray و جلوگیری از اجرای هم‌زمان چند نمونه.
- **حریم خصوصی:** بدون Hook کیبورد، بدون ضبط متن یا ارسال تله‌متری و بدون اتصال شبکه پس‌زمینه.

## دانلود و نصب

بعد از اجرای موفق گردش‌کار انتشار، فایل نصب ویندوز را از صفحه [GitHub Releases](https://github.com/MeysamBahadori/LangCue/releases) دریافت کنید:

`LangCue-Setup-0.2.0-preview.1-win-x64.exe`

این Installer برای **Windows 10/11 x64** است، برای کاربر جاری نصب می‌شود و نیازی به Administrator یا نصب جداگانه دات‌نت ندارد. اجرای خودکار هنگام ورود به ویندوز **اختیاری** است و به‌صورت پیش‌فرض فعال نیست. حذف برنامه از بخش Installed Apps ویندوز امکان‌پذیر است.

**توجه:** بسته این پیش‌انتشار هنوز امضای دیجیتال ندارد؛ ممکن است Windows SmartScreen هشدار ناشر ناشناس بدهد. حتماً منبع فایل را بررسی کنید.

**نکته درباره انتشار:** صرفاً ثبت کد در ریپو به معنی وجود فایل نصب نیست. ابتدا باید GitHub Actions اجرا و ساخت Installer با موفقیت تمام شود.

## اجرا از سورس

نیازمند ویندوز ۱۰/۱۱، SDK دات‌نت ۱۰ و اتصال اولیه به NuGet:

```powershell
git clone https://github.com/MeysamBahadori/LangCue.git
cd LangCue
dotnet restore LangCue.slnx
dotnet build LangCue.slnx -c Release
dotnet run --project src/LangCue
```

برای ساخت دستی بسته نصب، Inno Setup 6 را نصب کنید و در پوشه اصلی ریپو اجرا کنید:

```powershell
dotnet publish src/LangCue/LangCue.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -o artifacts/publish/win-x64
& "C:\Program Files (x86)\Inno Setup 6\ISCC.exe" "installer\LangCue.iss"
```

فایل نصب در مسیر `artifacts/installer` ساخته می‌شود.

## ساخت سریع Installer و انتشار دستی

اگر GitHub Actions پیش از اجرای Windows Job متوقف شد، پس از نصب **.NET 10 SDK** و **Inno Setup 6** می‌توانید بسته نصب را روی ویندوز خودتان با یک دستور بسازید:

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\scripts\Build-Installer.ps1
```

پس از آزمایش فایل نصب، برای ساخت اولین Release و ارسال فایل نصب به GitHub، ابزار **GitHub CLI** را نصب کرده و با `gh auth login` وارد حساب شوید؛ سپس:

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\scripts\Build-Installer.ps1 -Publish
```

این دستور اگر Release از قبل وجود داشته باشد، بدون جایگزینی فایل‌های آن متوقف می‌شود.

## تنظیمات

روی آیکون LangCue در System Tray راست‌کلیک کنید و گزینه **Settings...** را انتخاب کنید.

| گزینه | توضیح |
| --- | --- |
| Above | بالای نشانگر تایپ — پیش‌فرض |
| Ahead / Behind | جلو/عقب با توجه به RTL یا LTR زبان |
| Below | زیر نشانگر تایپ |
| Gap | فاصله ۰ تا ۸۰ پیکسل؛ پیش‌فرض ۱۴ |
| Background opacity | شفافیت پس‌زمینه ۴۰ تا ۱۰۰ درصد؛ پیش‌فرض ۷۸ |

تنظیمات در `%LOCALAPPDATA%\LangCue\settings.json` ذخیره می‌شوند و پس از آپدیت نیز حفظ می‌شوند.

## موارد پیشنهادی برای تست

۱. ابتدا نسخه قبلی را از منوی Tray با Exit LangCue ببندید و سپس نسخه جدید را اجرا کنید.

۲. Notepad، نوار آدرس Chrome و فیلدهای تایپ صفحات، از جمله کادر ChatGPT، را آزمایش کنید.

۳. در VS Code بخش‌های Editor، Search، Terminal و Chat و همچنین کادر پیام Claude را بررسی کنید.

۴. بین چند زبان نصب‌شده (مثلاً انگلیسی، فارسی، عربی و آلمانی) جابه‌جا شوید و هم زبان و هم محل نشانگر را بررسی کنید.

۵. جایگاه، فاصله و شفافیت را تغییر دهید و برنامه را دوباره اجرا کنید تا ذخیره تنظیمات مشخص شود.

۶. منوها و فیلدهای دارای Dropdown را نیز بررسی کنید.

## روش کار

یک Thread پس‌زمینه زبان فعال را از ویندوز دریافت می‌کند و برای پیدا کردن Caret به‌ترتیب از این روش‌ها استفاده می‌کند:

۱. `GetGUIThreadInfo` برای Caret استاندارد ویندوز.

۲. `AccessibleObjectFromWindow(OBJID_CARET)` برای محل Caret قابل‌دسترسی با MSAA.

۳. ‏UI Automation با `TextPattern2.GetCaretRange` و در بعضی حالت‌ها Selection خالی و گره‌های والد.

۴. اگر اطلاعات کافی وجود نداشته باشد، در بعضی کنترل‌های Edit از **لبه تقریبی فیلد** استفاده می‌شود؛ این مختصات دقیق Caret نیست.

برنامه محتوای تایپ‌شده یا کاراکترها را درخواست نمی‌کند.

## محدودیت‌ها

- بعضی ویرایشگرهای سفارشی، از جمله VS Code/Monaco و کادرهای گفت‌وگو، مکان واقعی Caret را از طریق APIهای دسترس‌پذیری ویندوز ارائه نمی‌کنند. ممکن است آیکون تقریبی نمایش داده شود یا پنهان بماند؛ برای پوشش کامل احتمالاً به سازگاری اختصاصی نیاز داریم.
- بعضی منوهای سیستمی و پنجره‌های دارای دسترسی بالاتر، از جمله صفحه امن UAC، امکان نمایش روی خود را نمی‌دهند.
- برای زبان‌های دارای IME، حالت‌های جزئی مانند Kana/Latin لزوماً با تغییر زبان ورودی ویندوز یکسان نیست. ابزار **زبان ورودی ویندوز** را نمایش می‌دهد، نه وضعیت دقیق تبدیل IME یا جهت پاراگراف.
- عملکرد در هر برنامه وابسته به Accessibility همان برنامه است و پوشش صددرصدی تضمین نشده است.

## ساختار ریپو

`LangCue.slnx` شامل تنها **یک پروژه WinForms با .NET 10** در `src/LangCue` است. پوشه `assets` آیکون برنامه، `installer` فایل Inno Setup و `.github/workflows` فرآیندهای Build و Release را نگه می‌دارد.

## مجوز

مجوز متن‌باز هنوز انتخاب نشده است. پیش از عمومی کردن ریپو باید یک مجوز مناسب انتخاب شود.
